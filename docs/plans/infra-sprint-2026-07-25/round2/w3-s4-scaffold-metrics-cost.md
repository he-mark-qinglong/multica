1. **`validate_metrics.py`**：
   ```python
   """Validate metrics.json against the 9-key schema + provenance fields."""
   REQUIRED_KEYS: dict[str, type] = {
       "sharpe_daily": float, "annualized_return": float,
       "max_drawdown_pct": float, "profit_factor": float,

   }
   PROVENANCE_KEYS = ("strategy", "cost_bps_rt", "data_window", "generated_at")
   ```
   - `validate_metrics(payload: dict) -> list[str]`：返回违例字符串列表（空 = 通过）。检查：
     - 缺 key → `"missing key: sharpe_daily"`；
     - 类型错 → 注意 **json 里 int 是 float 的子类陷阱**：`n_trades`/`n_bars` 要求 `isinstance(v, int) and not isinstance(v, bool)`；其余 7 个接受 `int`/`float`（json 无 float/int 区分必要时转 float）但拒绝 `bool/str/None/NaN/Inf`（`math.isfinite`）；
     - 取值域：`win_rate ∈ [0,1]`、`max_drawdown_pct ∈ [-1, 0]`、`n_trades ≥ 0`、`n_bars ≥ 0`，越界记违例。
   - `check_provenance(payload) -> list[str]`：缺 provenance key 各返回一条警告文本（**不入违例列表**）。
   - CLI（`main(argv=None)`，照 `run_strategy.py:217-257` 的 argparse 模式 + `if __name__ == "__main__"`）：`validate_metrics.py <path> [--report] [--strict-provenance]`。
     - 默认：schema 违例 → 退出码 1；无违例 → 0。provenance 缺失 → 打印 `WARN: ...`，**不影响退出码**；`--strict-provenance` 才把 provenance 缺失升为退出码 1。
     - `--report`：打印逐条结果（`OK/WARN/FAIL: <msg>`）+ 一行总结 `PASS (n warnings)` 或 `FAIL (n violations, m warnings)`。
     - 文件不存在 / JSON 解析失败 → 退出码 2。
