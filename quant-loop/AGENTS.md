## 1. Audit-by-replication rule (mandatory)

### Why this rule exists
`SMA-34855` ran a data-completeness audit that only checked
`~/multica/quant-loop/data/` and `~/multica/quant-loop/live_data/`. It
reported **"no 1m data exists anywhere at workspace level"** — a false
negative. Reality: the 1m bars live under per-strategy local copies
(`strategies/*/data/`) and under `data/perp_1m/` (which the audit missed
entirely). Re-running with the same naive directory list reproduces the bug.

### The rule
**Before drawing any "this symbol/timeframe exists / is missing" conclusion,
enumerate every data file in the workspace first.** The enumeration is the
single source of truth for the matrix. Build the matrix **from the enumeration
result only**, never from a hard-coded directory list.

```bash
# Step 1 — enumerate (mandatory, do not skip, do not paraphrase).
find ~/multica/quant-loop -path '*data*' -type f \
  -not -path '*/__pycache__/*' \
  -not -path '*/.pytest_cache/*' \
  -not -name '*.pyc' \
  -not -name '*.py' \
  -not -name '*.json' \
  -not -name '*.md' \
  -not -name '*.sha256' \
  -not -name '*.ipynb' \
  > /tmp/quant_loop_data_files.txt

# Step 2 — verify the count matches the canonical 234+ files
# (shared pool 30 + freqtrade user_data 4 + strategy-local copies 200+).
wc -l /tmp/quant_loop_data_files.txt
```

If the count is materially different from the canonical snapshot below,
**stop and report the discrepancy** before drawing any conclusions — a
changed count means data was added, removed, or the workspace moved.

**Canonical count as of 2026-07-19:** 253 data files (33 shared perp OHLCV
+ 10 funding + 4 freqtrade user_data + ~206 strategy-local copies across
65 strategies). Re-run periodically; the count grows when new strategies
land.

### Step 3 — classify each file into one of three buckets
The workspace has **three distinct data locations**. An audit that
collapses them into one will mis-report coverage.

| Bucket | Path pattern | Authority | Notes |
|--------|--------------|-----------|-------|
| **Shared pool — perp OHLCV** | `data/perp_{1m,2h,30m}/` and `live_data/` | All strategies | Canonical coverage claims must reference these paths. Currently 33 files. |
| **Shared pool — funding** | `data/funding/` | All strategies | Schema differs (`fundingTime` / `fundingRate`, not `open_time`). |
| **Freqtrade user data** | `freqtrade_v10/user_data/data/` | freqtrade only | Feather + parquet duplicates; framework-local. |
| **Strategy-local copies** | `strategies/*/data/` | Single strategy | Snapshot frozen at strategy-build time. May diverge from shared pool. **Must be reported separately** in any audit; never silently merged with the shared pool. |

### Step 4 — required outputs from any audit
Every data-completeness audit MUST produce, at minimum:

1. **The exact `find` command used** (copy-pasteable, reproducible).
2. **The total file count** the command returned.
3. **A (symbol × timeframe) matrix** with **two rows per cell** — one for
   shared pool (`live_data/` + `data/perp_*`), one for strategy-local
   copies (`strategies/*/data/`). Strategies that happen to have the
   same symbol/timeframe as the shared pool are NOT a substitute for
   the shared pool — they may be stale snapshots.
4. **A "verified vs inferred" column per cell** — verified means the
   audit actually opened the file and counted rows; inferred means the
   audit assumed content from the filename alone.
5. **Symlink audit** — run `ls -la` on `live_data/*.parquet` and
   `readlink -f` to expose any symlinks (the SMA-34855 ETH/SOL 4h bug
   was a symlink that secretly pointed at BTCUSD bars).

### Step 5 — language rule
Never write "no data exists anywhere" without first quoting the
`find` output that backs the claim. The same `find` invocation must be
re-runnable on a different day and produce the same answer.

## 3. Anti-patterns (audit failure modes)

| Anti-pattern | What it produces | Fix |
|--------------|------------------|-----|
| Hard-coded directory list (`ls data/ live_data/`) | False negative — misses 1m/5m/d data | Always `find` first |
| Reporting strategy-local copies as "shared pool coverage" | Over-counting — local copies may be stale | Report shared vs local as separate rows |
| Skipping the symlink audit | False positives (BTCUSD bars read as BTCUSDT) | Always `ls -la` + `readlink -f` |
| Inferring "no file" without quoting the `find` line | Unverifiable claims | Paste the command and the output |
| Reporting file count without distinguishing `.parquet` from `.csv` | Confusing coverage maps | Note both extensions explicitly |

## 5. Missing-bar detector (`scripts/missing_bar_detector.py`)

Canonical, library-first port of the original `live_data/verify_sma34898.py`
one-off. Use this for any future data-completeness audit instead of
copy-pasting the math into a new script.

### What it checks (per `(symbol × timeframe)` series)

| Check | What it means | Hard-fail? |
|---|---|---|
| `file_present` | path exists and is a regular file (symlink is flagged but not crashed) | yes if missing/symlink |
| `size_ok` | `> 1 KB` floor (a stray stub is not a series) | yes |
| `schema_ok` | columns include `open_time, open, high, low, close, volume` | yes |
| `nan_close_total` | `NaN` close count on full file | yes if > 0 |
| `ts_monotonic` | `open_time` non-decreasing | yes |
| `boundary_misalign_count` | `open_time mod bar_ms` — non-zero means the file is not on the timeframe grid | reported, not hard-fail |
| `missing_bars_in_window` | under-filled gaps in `[now - window, now]` | yes if > 0 |
| `full_file_missing_bars` | under-filled gaps over the entire file (sample-stride configurable) | reported, not hard-fail |
| `trailing_edge_short` | `last_open_time + bar_ms < now` — refresh lag | reported, not hard-fail (operational concern) |

`ok` is `False` only on hard-fails. Trailing staleness and boundary drift
are surfaced in the JSON report but do not crash the run.

### Library API

```python
from scripts.missing_bar_detector import (
    find_canonical_specs, detect_series, detect_path, run_grid,
)

specs = find_canonical_specs(Path("/home/smark/multica/quant-loop"))
reports = run_grid(specs, window_ms=7 * 24 * 60 * 60_000)
for r in reports:
    if not r.ok:
        log.warning("%s_%s bucket=%s reason=%s",
                    r.symbol, r.interval, r.bucket, r.error or "hard_fail")
```

### CLI

```bash
# Default run — scan every bucket, write JSON under live_data/.
python3 scripts/missing_bar_detector.py

# Restrict to shared pool + 1h/4h for a focused check.
python3 scripts/missing_bar_detector.py \
    --buckets shared_pool \
    --intervals 1h,4h \
    --window-days 7 \
    --out /tmp/mbd_report.json

# Full-file gap audit on huge files: sample every 100th timestamp.
python3 scripts/missing_bar_detector.py --full-file-stride 100
```

Exit code is `0` if every present file passes hard checks and no expected
file is missing; otherwise `1`.

## 6. Freshness dashboard (`scripts/freshness_dashboard.py`)

Companion to `scripts/missing_bar_detector.py`. Where §5 answers the
*structural completeness* question (gaps, schema, monotonicity),
this script answers the *operational freshness* question:

> **For every data file the workspace can prove exists, is its latest
> bar still inside the per-timeframe staleness budget?**

A file can pass §5 (no internal gaps, monotonic, on-grid) and still
fail §6 (refresh job died a week ago, no new bars since). Both
audits are needed; neither replaces the other.

### What it checks (per `(symbol × timeframe)` cell)

| Check | What it means |
|---|---|
| `file_present` | path exists and is a regular file (symlink flagged, not crashed) |
| `size_ok` | `> 1 KB` floor (a stray stub is not a series) |
| `schema_ok` | `open_time` (OHLCV) or `fundingTime` (funding) readable |
| `symlink_target` | if file is a symlink, the link target is reported so the SMA-34855 BTCUSDT_4h → BTCUSD_4h class of bug cannot recur silently |
| `age_ms` | `now - last_bar_ms` (uses last row of `open_time` / `fundingTime`) |
| `budget_ms` | per-TF staleness budget — see table below |
| `status` | one of `fresh` / `stale` / `missing` / `symlink` / `unknown` |

### Staleness budgets

Match `scripts/missing_bar_detector.FRESHNESS_SLACK_MS` (single source
of truth across both scripts — keep them in sync):

| Interval | Budget |
|---|---|
| `1m` | 5 min |
| `5m` | 10 min |
| `15m` | 20 min |
| `30m` | 35 min |
| `1h` | 65 min |
| `2h` | 2 h 5 min |
| `4h` | 5 h |
| `1d` | 26 h |
| `funding` | 9 h (8 h cadence + 1 h slack) |

### Per-cell status

| Status | Meaning | Hard-fail (exit 1)? |
|---|---|---|
| `fresh` | file present, last bar inside budget | no |
| `stale` | file present, last bar older than budget | **yes** |
| `missing` | expected path absent, or stub < 1 KB | **yes** |
| `symlink` | file is a symlink (target reported) | no — flagged for review |
| `unknown` | file present but schema unreadable | no — flagged for review |

### CLI

```bash
# Default run — write JSON + HTML under data/freshness/.
python3 scripts/freshness_dashboard.py \
    --workspace . \
    --json-out data/freshness/freshness-snapshot.json \
    --html-out data/freshness/freshness-dashboard.html

# Machine-only mode, emit JSON on stdout, no human summary.
python3 scripts/freshness_dashboard.py --workspace . --quiet > snap.json

# Override 'now' for tests / backfills.
python3 scripts/freshness_dashboard.py --workspace . --now-ms 1784351400000 --quiet
```

Exit code mirrors `missing_bar_detector`'s convention: `0` if no
present cell is past its budget and no expected cell is missing;
otherwise `1`. Symlinks and `unknown` rows are reported but do not
trigger a non-zero exit (the BTCUSDT_4h symlink is a known case).

### Outputs

* `data/freshness/freshness-snapshot.json` — machine-readable
  snapshot. Contains: `generated_at`, `workspace`, the literal
  `find` command used (§1 audit-by-replication), `files_seen`, a
  per-status / per-bucket / per-interval rollup, and one
  `FreshnessReport` per audited cell.
* `data/freshness/freshness-dashboard.html` — self-contained HTML
  (no external CSS/JS), opens directly from `file://`. Summary
  chips, per-interval breakdown, and a full per-cell table.
* The literal `find` command used is embedded in both outputs so a
  future operator can replay it on any day and confirm the cell
  count has not silently changed.
